## 2026-06-04

### 问题19：文本1错误识别单价和数量

**问题描述**：
导入小票时，文本1类型的小票一直错误识别单价和数量。特别是像"小王子薯片/薯条系列"这种换行显示的商品，经常把商品名中的数字当成数量，把小计当成单价。

**原因分析**：
1. 小票格式不统一，有的有完整4列（商品名、单价、数量、小计），有的只有2列（商品名、小计）
2. 之前的解析逻辑试图在信息不全时猜测单价和数量，导致经常猜错
3. 换行显示的商品名容易被误识别成多行

**最终解决方案**：
简化文本1的解析规则：所有文本1类型的小票，不管列数多少，都设置：
- price（单价）= 0
- quantity（数量）= 1
只保留商品名和小计信息

**关键结论**：
- 文本1规则不再尝试识别单价和数量
- 如果需要准确的单价和数量，应该使用文本2类型的小票
- 修改了 `backend/app/services/ocr_service.py` 中的 `build_item_type1` 函数

### 问题20：图片放大时图片和裁剪框不同步

**问题描述**：
在小票图片编辑页面，点击放大或缩小时，图片本身放大了，但裁剪框没有同步放大，导致裁剪框和图片内容不匹配。

**原因分析**：
之前的缩放效果只应用在 `<img>` 元素上，而裁剪框（ReactCrop）是独立的外层元素，两者没有一起缩放。

**最终解决方案**：
把缩放效果从 `<img>` 元素移到包裹图片和裁剪框的外层 `<div>` 上，这样两者就能同步缩放了。

**关键结论**：
- 修改了 `frontend/components/image-editor.tsx` 组件
- scale 变换现在应用在外层容器上，而不是直接应用在图片上
- 旋转效果仍然保留在图片上

### 问题21：防止以后再使用废弃字段

**问题描述**：
用户担心以后开发时会不小心再次使用已经废弃的 `unit` 字段，希望有预防措施避免重复犯同样的错误。

2. 在数据库 schema 定义中添加警告
3. 在后端和前端的类型定义文件顶部添加警告
4. 创建专门的 `DEPRECATED.md` 文档，记录：
   - 废弃的字段和废弃时间
   - 已清理的文件列表
   - 开发检查清单

**关键结论**：
- 每次开发前先查看 `DEPRECATED.md`
- 编写代码时注意查看各文件顶部的警告注释
- 使用 Grep 搜索 "unit" 检查是否有遗漏
- 如果不小心又用了废弃字段，要立即修正

### 问题22：React 生产环境错误 #418

**问题描述**：
生产环境出现 React 错误 #418，表示组件陷入了无限渲染循环。

**原因分析**：
recipe-drawer.tsx 中使用了 {condition && '字符串'} 模式，React 18+ 生产环境不允许这样写。

**最终解决方案**：
将问题代码改为三元运算符：{condition ? '文本' : null}

**关键结论**：
JSX 中使用 && 运算符时，右侧必须是 JSX 元素，不能是纯文本。

### 问题23：resolve_ingredient 工具 204 错误

**问题描述**：
直接用 `name_or_id` 查询 `ingredients` 表，如果传入的是名称而非 ID，`eq("id", name_or_id)` 可能返回 204，导致 Supabase SDK 抛出 APIError。

**原因分析**：
没有区分 UUID 和名称的查询方式，直接使用 ID 查询字段来查询名称。

**最终解决方案**：
1. 添加 UUID 格式检测，判断输入是否为 UUID
2. 如果是 UUID，使用 `eq("id", name_or_id)` 查询
3. 如果不是 UUID，先使用 `eq("name", name_or_id)` 精确匹配，再使用 `ilike` 模糊匹配
4. 如果仍未找到，返回友好提示，询问用户是否需要创建新食材（默认数量为0）
5. 捕获所有异常，记录详细日志并返回错误信息给 Agent

**关键结论**：
- 修改了 `backend/app/routers/ai_tools.py` 中的 `resolve_ingredient` 函数
- 添加了完整的错误处理机制
- 确保工具调用失败后 Agent 仍能输出结果
