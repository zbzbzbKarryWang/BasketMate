## 🐛 问题修复与复盘

- **batch-update-quantity 接口 422 错误**
  - 问题现象：前端调用接口返回 422 Unprocessable Entity
  - 根本原因：后端使用 `List[dict]` 接收请求体，但 Pydantic 验证失败，缺少必填字段验证
  - 最终解决方案：新增 `BatchUpdateItem` Pydantic 模型，定义必填字段 `id` 和 `quantity`，修改路由使用模型验证

- **日志接口 500 错误**
  - 问题现象：`GET /api/logs/recent` 返回 500 Internal Server Error
  - 根本原因：两处问题——（1）日志文件路径不一致，后端写入 `/logs/app.log` 但读取 `/app/logs/app.log`；（2）`PlainTextResponse` 参数名错误，`content_type` 应为 `media_type`
  - 最终解决方案：统一路径为 `/logs/app.log`，修正参数名为 `media_type`

- **日志文件路径不一致**
  - 问题现象：日志写入成功但接口读取不到
  - 根本原因：Dockerfile 创建 `/app/logs`，docker-compose 挂载到 `./backend/logs:/app/logs`，但实际代码使用 `/logs`
  - 最终解决方案：统一修改为 `/logs` 路径，Dockerfile 创建 `/logs`，docker-compose 挂载为 `./backend/logs:/logs`

- **refresh 接口性能问题**
  - 问题现象：`POST /api/plans` 耗时 2.31 秒（超目标 1 秒）
  - 根本原因：`compute_pending_items` 函数中循环内重复查找价格最低价，O(n²) 复杂度
  - 最终解决方案：预构建价格映射 `price_map`，将查找复杂度降为 O(1)，同时添加详细耗时日志分段计时

- **日志系统架构**：使用 Python `logging` 模块 + `RotatingFileHandler`，单文件最大 10MB，保留 2 个备份
