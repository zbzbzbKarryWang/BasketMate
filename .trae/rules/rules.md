## 数据与命名
- 所有字段名、JSON Key 必须与数据库定义完全一致（snake_case）。不一致时，先问我以谁为准。

## 代码修改原则
- 修改任何字段或模型时，必须同步修改所有引用该字段的前后端代码。
- 新旧规则冲突时，一律用新规则，彻底删除旧逻辑，禁止兼容。

## 错误与日志
- 后端每个新增或修改的路由，必须添加结构化的 `logger.info()` 日志，包含操作名称和关键参数/结果。
- 后端日志中间件必须根据 HTTP 状态码自动选择日志级别（2xx→INFO，4xx→WARNING，5xx→ERROR）。
- 所有返回 4xx 或 5xx 的接口，必须在返回前记录详细的错误日志，包含请求体和具体错误信息。

## 接口与数据流
- 后端所有 API 返回 `ApiResponse` 格式：`{success: bool, data: ..., message: ...}`。
- 前端收到响应后，只检查 `response.success`：true 用 `data`，false 显示 `message`。
- 数据修改必须先通过 API 持久化，等待返回结果再刷新前端，不得仅修改前端本地状态。

## 任务执行准则
- 指令模糊、存在多种方案、矛盾或冲突时，向我询问并确认后执行。
- 无法完成的步骤必须明确指出，并说明原因和替代方案。
- 全局修改完成后，必须用搜索命令验证旧代码已全部清理，并输出验证结果。
